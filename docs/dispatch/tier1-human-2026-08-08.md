### Row 1 — Start & persist

Five constants, all bare `PROPOSED (2026-08-01)`, no ruling anywhere in their own entries.

- **`Autosave.INTERVAL_SECONDS`** — candidate **90.0** (current): spec.md → Pacing
  Constants states "~1–2 min," and 90.0 is the midpoint — the same midpoint-of-a-stated-
  band move already ruled twice elsewhere (row 2's `ZOOM_DEFAULT_TILES = 14.0` from
  gdd.md's "~12–15-tile" band, and row 10's `GRACE_WINDOW_SECONDS = 12.0` from spec.md's

  a fresh guess. Alternative **60.0** (band floor): no precedent for picking the floor
  instead of the midpoint anywhere in this project's decided constants — flag as the less-
  supported option.
- **`WorldSnapshot.SAVE_VERSION`** — candidate **1**: the only sensible value for a first
  save format: no precedent needed, essentially a formality rather than a judgment call.
- **preset `display_name` "Meadow Start"** — candidate **"Meadow Start"** (current):
  matches the "[Terrain] Start" naming convention gdd.md's own preset examples use
  ("Jungle Start," "Desert Start," "Farm Start"), even though none of those three is
  literally the v1 preset. No precedent found for an alternative name — pure judgment
  call if the human wants something else.
- **`DEFAULT_WORLD_NAME` "Wildhaven"** — candidate **"Wildhaven"** (current): matches the
  game's own title, and the field's own rationale (pre-filled so a kid can press "Let's
  go!" without typing) is satisfied by any string. Alternative **"My Meadow"** (more
  personal/kid-directed, ties to the preset name above): no precedent found — pure
  judgment call.
- **`MIN_SAVED_WORLD_TILES` / `MAX_SAVED_WORLD_TILES` = 1 / 128** — candidate **1 / 128**
  (current): the 128 half is not really a fresh guess — gdd.md → World Structure states

  repeated in spec.md Open Question #18 and in the Performance section's "~16k tiles at

  cap constant — ruling both together keeps them from drifting apart. 1 as a floor is
  the obvious "smaller isn't a world" sanity bound; no alternative surfaced.
